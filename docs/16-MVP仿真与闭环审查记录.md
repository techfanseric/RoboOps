# RoboOps MVP 仿真与闭环审查记录

整理日期：2026-07-06
审查对象：`/Users/ericyim/RoboOps/app`

## 1. 审查目标

本轮审查专门排查“看起来像演示壳”的功能设计：

- 不允许正式界面出现后台内账号一键切换、演示账号、演示操作员等口径。
- 不允许控制台在未登录时直接可访问，也不能只有当前账号展示而没有退出登录。
- 不允许高风险动作点一下就改经营事实，必须有原因、影响、审批、审计或同步记录。
- 不允许表单只有占位外观却缺少必填校验、处理结果或回退依据。
- 不允许状态机缺少边界，例如任务重复开始、异常重复退款、未完成就关闭。
- 不允许报表同步记录暴露“本地状态”“手工回调”等前端模拟口径。

## 2. 本轮发现与修正

| 问题 | 风险 | 修正 |
| --- | --- | --- |
| 报表同步记录显示“本地已应用”“本地待回滚”“本地状态” | 暴露前端模拟状态，不像真实后台 | 改为“业务已记录”“待补偿处理”“业务状态”，同步失败后的高风险处理统一为“补偿处理” |
| 代码中仍保留 `resolve-api-operation` 手工服务端回调 | 即使 UI 不暴露，也会误导后续实现继续做手工回调 | 删除 action、reducer 分支和回调处理函数，报表只保留提交同步、等待确认和补偿处理 |
| 没有登录页和退出登录 | 账号虽然不再能一键切换，但控制台仍像默认已登录状态 | 增加 `/login`、未登录路由守卫、账号密码校验、侧边栏退出登录和登录/退出审计 |
| 登录态没有会话边界 | 控制台仍像永久登录，无法表达真实账号安全要求 | 登录成功生成会话号和有效期；会话过期后回到登录页，登录失败写入认证审计 |
| 工作台只有统一经营总览 | 不同岗位登录后都看同一套入口，不像真实业务系统 | 新增“当前账号职责”，按角色展示工作重点、处理节奏、动作边界、权限包和优先队列 |
| 执行角色在首页看到财务和配置发布快照 | 现场维护员等角色不该看交易额、退款售后和全局配置发布 | 工作台按报表和配置发布权限收缩敏感区块；无权限时改显示交付完成、现场确认和设备状态 |
| 能看报表就能提交同步或补偿 | 数据查看员、审计员应只读查看，不能触发服务端同步或补偿处理 | 新增接口同步动作策略，提交同步和补偿处理按角色、数据范围和同步状态禁用；角色页展示动作矩阵 |
| 需求来源被做成产品入口 | 项目材料可以归档，但“这个需求从哪里来”不应体现在业务系统中 | 已移除资料归档页面、资料权限包和资料数据模型；项目材料仅保存在 `materials/` 目录，业务系统只保留处理记录和审计日志 |
| “新异常”按钮点击后直接创建异常 | 缺少点位、来源、等级、负责人和情况说明，不符合真实登记流程 | 改为异常登记抽屉，必填点位、异常类型、来源、等级、负责人和情况说明；提交后写入异常、处理记录、审计和同步记录 |
| 任务动作不看任务状态 | 已在处理的任务仍可重复开始，未开始任务也可提交结果 | 补任务状态机：未开始才能开始，处理中才能提交结果，已解决不能继续处理 |
| 异常动作不看异常状态 | 可重复转退款、重复派单，未完成处理也可关闭 | 补异常状态机：已有退款不能重复转退款，已有现场任务不能重复派单，未完成处理不能关闭 |
| 异常处理抽屉的“影响结论”非必填 | 处理记录缺少影响判断，无法复盘 | 异常推进、转任务、转退款、关闭均要求填写处理说明和影响结论 |
| 任务“标记解决”不要求处理结果 | 任务可被空泛关闭 | 标记解决时必须填写处理说明和处理结果 |
| 通用配置发布不要求填写“发布前” | 审批人无法判断差异和回退依据 | 新建发布必须填写发布前、发布后、影响范围和发布原因 |
| 发布和角色授权范围靠手填字符串 | 后续审批、权限和审计无法稳定判断影响对象 | 增加结构化范围选择器；通用配置发布、对象级发布和角色实例授权写入 `scopeRef`，详情页展示范围层级和对象 |
| 已发布配置没有受控回退入口 | 配置出错后只能人工再改，缺少回退原因、审批和审计 | 对象级发布可申请回退，生成回退发布和审批；审批通过后按原变更记录反向应用，并标记来源发布已回退 |
| “生成配置”文案过泛 | 容易误解为一键启用正式权限 | 改为“生成角色草案”，后续仍需绑定账号、提交审批、审批通过后才启用 |
| 角色实例草案把“客户配置”显示在账号列 | 承担方式和真实账号混在一起，看起来像假数据 | 未绑定时显示“待绑定账号 / 建议承担方”，范围列显示“待选择范围 / 建议范围” |
| 角色实例启用后缺生命周期 | 权限一旦开通就没有复核、有效期和回收入口 | 角色实例增加有效期、下次复核、复核审批和回收审批；审批通过后才延长有效期或回收权限，并写入 L4 审计/同步记录 |
| 复核/回收直接生效 | L4 权限生命周期动作只填原因就立刻改变权限，不符合真实权限治理 | 复核/回收改为先生成审批单；审批前权限保持原状，审批通过后才延长有效期或回收权限 |
| 用户邀请只能停在待接受队列 | 无法验证受邀人如何成为登录账号，也容易误以为邀请自动授予权限 | 增加独立邀请接受页；已登录会话必须先退出，受邀人设置密码后只创建“待授权用户”账号，登录后只显示授权等待页，过期邀请被拦截，角色权限仍需管理员绑定实例并审批 |
| 点位级角色范围被城市字段放大 | 角色实例范围写成“品牌 / 城市 / 点位”时，系统可能把它当成城市范围，泄露同城其他点位 | 范围匹配优先识别明确点位名；只要范围内包含具体点位，就只按这些点位授权 |
| 业务负责人能审批也能配置角色实例 | 审批者和权限管理员混在一起，容易形成自批自管的假闭环 | 角色实例动作新增管理策略：只有平台支持、租户管理员或“用户权限管理包”可发起配置、复核、回收；业务负责人可查看和审批，但不能自己提交角色管理动作 |
| 审批队列只显示前 6 条 | 真实运营中后续待审批角色、退款或配置可能被藏在列表外 | 审批队列改为待审批项优先，并展示当前账号可见的全部审批记录 |
| 默认高度下退出按钮贴底 | 左侧导航项较多时，账号区被挤到视口底线，退出按钮可能难以点击 | 侧边栏改为品牌区固定、导航区可滚动、账号区固定；默认 1280×720 视口下退出按钮完整可见并可点击 |

## 3. 当前闭环规则

- 账号身份由登录态决定；未登录只能访问 `/login`，侧边栏只展示当前账号、会话有效期并提供退出登录，不提供后台内切换身份。
- 工作台先说明当前账号的职责、处理节奏、动作边界和优先队列，再展示经营总览；财务指标、退款售后和配置发布快照必须按权限收缩。
- 菜单可见不等于动作可执行；角色页必须能解释当前账号对配置、审批、导出、设备命令、接口同步和补偿处理的动作边界。
- 权限实例不是永久生效；启用后必须带有效期和复核时间，复核或回收都必须填写依据并进入审批，审批通过后才改变权限生命周期。
- 角色权限页允许不同角色查看不同范围内的权限事实，但角色实例的配置、复核和回收属于 L4 管理动作，必须由平台支持、租户管理员或拥有“用户权限管理包”的账号发起。
- 用户邀请只负责创建基础登录账号；受邀账号默认没有业务权限，也不能提前看到经营数据，必须经过角色实例绑定、审批和后续复核。
- 权限范围同时出现品牌、城市和点位时，点位名优先级最高；明确点位授权不能被上级城市字段放大。
- 配置类动作先生成发布和审批，不直接改当前经营配置。
- 配置回退也必须走发布和审批；审批通过后才会按原发布差异反向应用，并保留来源发布、回退发布、原因和审计记录。
- 发布和角色授权范围必须能落到租户、品牌、组织、城市、点位、设备或场景模板等结构化对象；当前前端已写入 `scopeRef`，后续由服务端 ID 模型接管。
- 设备低风险命令要求填写执行依据并写入命令、设备事件和审计；高风险命令进入审批。
- 异常处理必须留下处理说明和影响结论；退款、关闭等高风险动作进入审批。
- 任务开始和解决受状态机限制，解决任务必须写明结果。
- 服务端同步记录表达业务状态、同步状态、失败原因和补偿处理，不显示前端本地模拟口径。

## 5. 后续仍要防止的情况

- 任何新动作都必须回答：谁发起、为什么做、影响什么、是否需要审批、成功/失败后如何留痕。
- 任何新状态都不能只作为颜色标签，必须能说明来自哪个经营事实。
- 任何新表单都不能只靠占位提示，关键字段必须参与校验。
- 任何新按钮都不能只改变前端视觉状态，必须写入对应的经营对象、处理记录、审批、审计或同步记录。
- 任何样例账号都只能用于验收矩阵，不能出现在正式界面的身份切换操作里。
