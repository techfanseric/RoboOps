# RoboOps 项目材料保存规范

整理日期：2026-07-06

## 1. 定位

本规范只约束 RoboOps 立项、调研、访谈、会议和复盘材料在项目仓库中的保存方式，不定义产品后台功能。

需求来源、客户访谈原文、内部讨论录音、转录文本和总结纪要属于项目管理与交付材料。它们可以帮助团队回溯判断，但不应在 RoboOps 产品系统中体现为“资料归档”“需求来源”或类似一级模块。

产品系统中只保留业务对象本身需要的记录：

- 异常处理记录。
- 任务处理结果。
- 订单/服务请求备注和售后沟通记录。
- 配置发布差异、审批意见和回退原因。
- 操作日志、权限日志和高风险动作记录。

## 2. 项目目录

项目材料统一放入仓库内的 `materials/` 目录：

```text
materials/
  audio/
  transcripts/
  summaries/
```

这些路径仅供项目团队使用，不进入产品 UI、权限包、菜单、路由或业务数据模型。

## 3. 文件格式

| 类型 | 标准格式 | 用途 | 要求 |
| --- | --- | --- | --- |
| 录音 | `.m4a` | 会议、访谈、现场复盘等原始音频 | AAC-LC，单声道，64-96 kbps，44.1 kHz 或 48 kHz |
| 低带宽录音 | `.opus` | 浏览器录音、移动端低带宽上传 | Opus，24-48 kbps；作为可选输入格式 |
| 原始转录 | `.txt` | 保留语音转文字的原始结果 | UTF-8；保留说话人、时间戳和原始表达 |
| 总结纪要 | `.md` | 沉淀结构化结论、决策和待办 | Markdown；关联对应录音和转录路径 |

命名规则：

```text
YYYYMMDDHHMMSS-topic.audio.m4a
YYYYMMDDHHMMSS-topic-transcript.txt
YYYYMMDDHHMMSS-topic-summary.md
```

## 5. 产品边界

当前 React/Vite MVP 不做：

- 资料归档一级入口。
- 资料资产列表。
- 录音、转录、总结文件在后台中的路径展示。
- 基于“需求来源”的权限包、菜单或数据模型。
- 自动上传、转码、转写和总结。

如果后续真实业务需要保存客服录音、现场照片或设备排障附件，应作为对应业务对象的附件或处理记录能力设计，并进入审计日志，而不是复用项目材料归档概念。
