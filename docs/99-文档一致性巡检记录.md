# RoboOps 文档一致性巡检记录

整理日期：2026-07-05
巡检范围：`00-项目索引.md` 至 `17-项目材料保存规范.md`

## 1. 巡检结论

本次从头到尾复核后，文档主线已经统一：

- RoboOps 是机器人商业运营平台。
- 饮品亭/咖啡亭是第一批样板场景，产品边界覆盖更多机器人商业场景。
- 本期 MVP 目标是搭可配置框架，并跑通一个样板场景。
- 甲方大概率缺少完整商业运营团队，因此系统需要给出默认运营模型、角色模板、权限模板和异常分派方案。
- 不再把关键运营设计问题原样抛给甲方；后续向甲方/内部拿的是事实资料、配置选择和实施约束。

巡检后，没有发现会推翻产品方向的根本冲突。已修正的主要问题集中在 MVP 边界、角色权限粒度、待确认问题口径和后续文档编号。

## 3. 当前统一术语

| 建议术语 | 避免写死的语义 | 说明 |
| --- | --- | --- |
| 点位/场景单元 | 门店 | 可覆盖亭子、展点、服务站、柜体、工作站 |
| 品牌或组织 | 品牌组织 | 面向用户表示业务归属入口，既可按品牌运营，也可按组织/区域运营 |
| 商品/服务 | 饮品 | 可覆盖饮品、零售商品、机器人服务、预约服务 |
| 订单/服务请求 | 饮品订单 | 可覆盖交易订单、服务单、任务请求 |
| 履约状态机 | 制作流程 | 可覆盖制作、递送、讲解、服务执行 |
| 异常/事件 | 故障告警 | 异常要进入分派、处理、关闭闭环 |
| 任务/工单 | 运维单 | 可覆盖补料、巡检、维修、人工确认、客服处理 |
| 资源/耗材 | 物料/料仓 | 饮品场景可展开为原料和库存，其他场景可表达耗材 |
| 配置发布 | 模板下发 | 覆盖商品、点位、设备、场景、状态、异常规则的发布 |

## 4. 当前统一 MVP 边界

### 4.1 必须纳入

- 租户/客户边界、品牌、组织、角色基础框架。
- 场景模板，至少包含饮品亭和通用机器人服务站两个样板。
- 点位管理和点位绑定机器人/设备。
- 机器人/设备台账、在线状态、运行状态、事件日志。
- 商品/服务目录，支持自定义属性、规格/SKU、上下架、适用点位。
- 订单/服务请求列表、详情、生命周期状态。
- 轻量状态机，支持底层状态和场景显示名。
- 异常中心，支持异常生成、分派、处理、关闭。
- 配置发布记录。
- 工作台看板。
- 用户、角色模板、权限包、数据范围、基础审批策略。
- 操作日志和高风险动作留痕。

### 4.2 可以简化

- 多租户：模型保留，第一版不做完整 SaaS 商业化能力。
- 多品牌：模型保留，界面可先开放单品牌或少量品牌。
- 财务：先做收入、退款和导出留痕，不做完整结算/分账。
- 工单：先做异常处理记录和轻量任务，不做完整工单系统。
- 配置发布：先做记录、范围、版本和状态，不做复杂灰度/回滚。
- 小程序：先打通订单/支付/状态，不把消费者端完整产品纳入后台 MVP。

### 4.3 暂不纳入

- 完整配方引擎。
- 完整库存、仓储、采购、补货。
- 完整财务结算、分账、对账。
- 完整 OTA、远程控制、远程调试。
- 复杂工作流引擎。
- 会员、营销、CRM。
- 高级 BI 和自定义报表设计器。
- 多机器人空间调度。
- 完整客服系统。

## 5. 当前统一角色权限口径

角色权限是可配置模型：

> 用户 + 角色模板/角色实例 + 权限包 + 数据范围 + 审批策略 + 异常分派规则 + 审计日志

MVP 至少应内置这些角色模板：

- 平台支持。
- 租户管理员。
- 业务负责人。
- 运营负责人。
- 点位负责人。
- 商品/配置管理员。
- 配置发布人。
- 客服/售后。
- 退款审批人。
- 机器人/设备运维。
- 现场维护员。
- 财务/结算。
- 数据查看员。
- 审计员。
- 试运行操作员。

系统应支持客户一人多岗，但必须显性化职责边界，尤其是：

- 退款发起和退款审批尽量分离。
- 配置编辑和配置发布尽量分离。
- 设备高风险命令需要二次确认和审计。
- 外部供应商只能看到对应点位、设备或工单。
- 每类异常必须有默认负责人。

## 6. 当前仍缺的关键细节

以下是后续真实接入、试点上线和版本迭代需要继续补齐的内容。

### 6.1 事实资料

- 现有 API 文档。
- 小程序下单链路。
- 支付状态回调。
- 订单状态字段。
- 设备/机器人状态字段。
- 错误码/异常码。
- 真实异常案例。
- 深圳试点点位和设备组合。
- 当前支付、退款、客服、现场维护责任主体。
- 两个月窗口期的准确里程碑和工程资源。

### 6.2 工程化与真实接入

- 真实 API 接口定义和字段映射。
- 登录认证和当前账号来源。
- 服务端角色权限、菜单权限、数据范围、审批策略和后端二次校验的真实执行。
- 邀请邮件/短信投递、服务端 IAM、服务端范围模型、版本锁和冲突处理。
- 异常处理、退款、任务解决、配置发布的服务端表单、校验和失败回滚。
- 详情页独立路由和跨模块跳转的进一步产品化。
- 前端状态持久化或服务端状态同步。

### 6.3 需要进一步细化的设计问题

- 订单/服务请求底层表最终命名：`orders`、`service_requests` 还是 `business_requests`。
- 场景模板字段配置的第一版粒度。
- 配置发布是否需要第一版审批。
- 高风险设备命令的第一版范围。
- 试运行环境是否面向展会、样板间还是客户沟通。
- RoboOps 第一版是平台代运营优先，还是客户自助使用优先。

## 7. 后续迭代 PRD 的约束

后续迭代 `07-PRD-v0.1.md` 或新增版本 PRD 时，应遵守以下约束：

- 不再写成饮品亭后台 PRD。
- 不再把角色写死为固定岗位。
- 不再把客户无法回答的问题作为 PRD 前置条件。
- 所有饮品语义必须落在“饮品亭场景模板”里，不能进入核心模型。
- PRD 必须包含团队搭建向导、角色模板、权限包、异常分派规则。
- PRD 必须明确哪些是 MVP 必做、哪些只是扩展位、哪些明确暂不做。
