# 旧后台能力补全实施记录

## 实施口径

本轮以甲方旧后台源码为业务规则基线，在 RoboOps 既有信息架构内补齐缺失能力。实现形式为可交互前端业务仿真与 API-ready 领域层：领域状态按租户持久化到浏览器 `localStorage`，同租户角色共享业务事实、视图再按账号与点位范围裁剪；关键规则由纯领域函数或 reducer 执行，并以 Vitest 做确定性回归。

本轮不接入真实数据库、MQTT、Kafka、OSS、通知渠道或打印机；这些外部能力保留凭证、任务、状态、失败与审计界面，便于后续替换为服务端 API。

## 新增能力与入口

| 入口 | 能力 |
| --- | --- |
| `/resources` | 规格模板、执行配方、工艺步骤、资源耗材、料仓、效期方案、当日批次、报损、首次打印与补打 |
| `/devices/operations` | 硬件能力、配置模板与下发、料仓标定、离线策略、维护方案、软件包与升级策略 |
| `/orders/operations` | 点位扩展资料、手工单防重、订单前置校验、首次下发、显式重试、执行与打印记录 |
| `/reports/advanced` | 订单、支付、商品、物料、损耗、设备、点位等细分报表与异步导出 |
| `/roles/platform` | 企业与应用、平台账号、菜单权限、系统默认设置、平台日志与异步任务 |
| `/integrations` | 开发者申请、企业授权、OpenAPI/MQTT 凭证、事件订阅、数据同步与调用审计 |

资源配方、设备状态和订单报表之间通过只读领域快照适配器联动：订单下发读取当前租户的最新启用配方、工艺、物料步骤和设备回执；七类报表由订单、点位、资源料仓、标定与损耗事实聚合生成。

## 保留的关键业务规则

- 企业隔离和点位数据范围先于业务动作判定。
- 点位名称、编码和第三方编码唯一；设备 SN 只允许字母数字且大小写不敏感唯一。
- 设备禁止跨企业或跨点位直接改绑；供应商授权和型号供应商限制必须满足。
- 配方要求规格、物料和启用工艺；全国、区域、点位范围冲突时停用旧版本并保留审计。
- 料仓数量为整数，补料不超过容量、出料不超过余量、容量不得低于现有余量。
- 效期方案同点位唯一；批次只允许当天且防重复；过期或完全报损批次禁止打印；首次与补打分开记录。
- 维护方案同设备同类型唯一，空步骤不可下发，删除方案不删除历史发布记录。
- 软件包分 App、固件、Web 三类，同类型 MD5 可复用，依赖存在时禁止删除；升级策略最多十条且启用后锁定编辑。
- 手工订单防重；下发前再次校验点位、设备、配方和步骤；重复发送必须使用显式重试并独立留痕。
- 异步任务最多展示最近 50 条；处理中任务不可清理；超过五分钟无进度转失败。
- 密钥只展示掩码；企业授权同时受权限范围、点位范围、启用状态和有效期约束。

## 已纠正的旧实现问题

- 统一软件版本字段，避免 `os_version` / `web_version` 混用。
- 范围集合按数组处理，不对数组读取 `.value`。
- 设备标识按字符串处理，不读取不存在的 `machine_id.value`。
- 版本使用明确的版本号与状态约束，不做普通字符串大小比较。
- 对旧源码中的空实现、TODO 和重复兼容端点，仅保留可验证的业务意图，不复制缺陷。
