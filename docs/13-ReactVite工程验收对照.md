# RoboOps React/Vite 工程验收对照

整理日期：2026-07-05

## 1. 验收结论

RoboOps 已从静态 MVP 升级为正式 Vite + React + TypeScript 前端工程。当前工程不再依赖旧的 `app.js` 与根目录 `styles.css`，前端源码以 `app/src/` 为准。

本轮升级符合前期规划：系统定位为“机器人商业运营平台”；饮品亭是可配置场景之一。MVP 已覆盖工作台、品牌或组织、场景模板、点位、设备、商品/服务、订单/请求、异常、任务、配置发布、报表和角色权限，并能跑通一条可运营闭环。

## 2. 工程实现

| 范围 | 当前实现 |
| --- | --- |
| 技术栈 | Vite、React、TypeScript、React Router、Lucide React |
| 入口 | `app/index.html`、`app/src/main.tsx`、`app/src/App.tsx` |
| 页面 | `app/src/pages/` 按一级模块拆分 |
| 组件 | `app/src/components/` 承载表格、徽标、详情、列表、按钮等通用组件 |
| 数据 | `app/src/data/mockData.ts` 承载本地样例租户、品牌、点位、设备、请求、异常、任务、退款和权限数据 |

| 服务层 | `app/src/services/operations.ts` 统一处理筛选、派生指标、异常动作、任务动作、配置发布、配置变更、审批处理和团队建议 |
| 样式 | `app/src/styles.css` 承载应用级样式与响应式规则 |
| 状态保存 | `app/src/App.tsx` 通过 localStorage 保存当前操作状态，避免刷新后丢失前端验证结果 |

## 5. 后续缺口

这些缺口不阻塞当前工程验收，但会影响真实试点上线：

- 权限：当前已接入本地登录页、退出登录、会话有效期、登录失败审计、前端样例角色、角色实例、菜单、路由守卫与数据范围控制，但还没有企业账号/SSO、服务端授权、服务端权限矩阵和后端二次校验。
- 角色实例：当前已具备前端权限审批流、有效期、复核审批、回收审批和 L4 审计；复核/回收审批通过后才改变权限生命周期。真实上线时仍需由服务端 IAM 执行，并补充多级审批、委托审批、自动到期冻结和定期复核任务。
- 角色管理：当前已在前端区分查看、管理发起和审批处理；真实上线仍需由服务端权限矩阵和 API 校验保证同样规则。
- 审批：当前已支持单级审批、自审拦截、角色和范围判断，但还没有金额阈值、影响范围阈值、多级审批和超时升级。
- 配置：商品/服务目录、点位配置、场景模板、品牌、组织和设备配置已具备基础发布联动；通用配置发布和对象级发布已写入结构化范围；对象级配置发布已具备受控回退申请和反向应用；租户/客户开通已能生成初始业务骨架，用户邀请、接受、账号创建和角色实例审批链路已跑通；设备命令已具备前端受控闭环。后续需要补字段级校验、邮件/短信投递、服务端 IAM、服务端版本锁、冲突处理和持久化。
- API：当前已具备 API operation outbox、接口路径映射、同步生命周期和补偿处理台；后续需要接真实 HTTP client、自动重试、服务端分页、真实数据同步和对象级补偿执行。
- 附件能力：若后续真实业务需要客服录音、现场照片或排障附件，应挂在订单、异常、任务或设备记录下，并进入审计日志，不再单独建设“资料归档”模块。
- 动作权限：当前前端已能展示动作权限矩阵，并控制报表同步/补偿、异常、任务、设备命令、配置发布、审批和角色管理动作；后续仍需服务端权限矩阵和 API 二次校验。
- 审计：当前为前端样例留痕，后续需要服务端不可篡改日志、前后值和操作者来源信息。
- 数据范围：当前可按账号范围限制筛选、详情、审批和日志；发布和角色实例已先写入结构化范围对象，但还不是完整的服务端租户、品牌、组织、点位、设备组授权模型。
- 角色首页：当前已补当前账号职责和角色队列；现场维护、客服售后、财务结算、审计复核仍需要更深的专属首页组件。
