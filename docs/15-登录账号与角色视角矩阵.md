## 1. 结论

角色权限不能只验证“按钮是否禁用”。RoboOps 的客户很可能是从零搭建商业运营团队，因此每一种角色登录后都应该有明确的工作场景、可见菜单、数据范围和动作边界。

当前工程已补齐登录账号视角：

- 未登录访问控制台会进入 `/login`，登录成功后才渲染运营控制台。
- 侧边栏账号区域提供退出登录，退出后回到 `/login`。
- 侧边栏底部只显示当前登录账号、角色和数据范围，不提供后台内一键切换身份。
- 一级菜单会按当前账号有效角色和权限包过滤。
- 直接访问无权限 URL 会进入“无菜单权限”说明页。
- 工作台新增“当前账号职责”，按登录角色展示工作重点、处理节奏、动作边界、权限包和优先队列。
- 工作台中的财务指标、退款售后阶段和配置发布快照按菜单/权限包收缩；现场维护员等执行角色不显示交易额、退款售后或配置发布列表。
- 角色权限页新增“登录账号与职责”，用于查看账号、角色、数据范围、工作重点和可见菜单。
- 角色权限页新增“当前账号动作权限”，把查看、配置、审批、导出、设备命令、接口同步和补偿处理分开判定。
- 角色权限页继续展示当前账号的权限来源、有效权限包、菜单授权来源、审批队列和操作日志。
- 角色实例配置已使用结构化范围选择器，提交时同时写入可读数据范围和 `scopeRef`，便于后续接服务端授权模型。
- 受邀账号通过独立邀请页接受邀请；接受后只获得“待授权用户”基础账号，工作台只显示授权等待状态，不展示经营数据；业务权限必须由管理员绑定角色实例并走审批。
- 角色页的“可查看”和“可管理”已分离：业务负责人可以查看权限和处理审批，但不能自己提交角色实例配置、复核或回收；平台支持、租户管理员或拥有“用户权限管理包”的账号才可以发起这些 L4 管理动作。

## 3. 登录视角原则

- 平台支持可以跨租户查看，但真实上线必须记录客户数据访问原因、操作来源和审批依据。
- 租户管理员负责组织、品牌、用户和数据范围，不默认拥有退款审批和设备高危命令。
- 业务负责人看经营结果和关键审批，不承担日常设备操作。
- 运营负责人承担日常闭环，可以看到点位、请求、异常、任务、报表和配置协同。
- 点位负责人只处理自己点位或少量点位的状态、异常、任务和请求。
- 商品/配置管理员、场景模板管理员、配置发布人、配置审批人应该分工明确，避免编辑、发布和审批长期集中在一个人。
- 客服/售后可以发起退款和记录沟通，但不能审批自己的退款。
- 机器人/设备运维可以处理设备异常和受控命令，高风险命令需要审批。
- 现场维护员应优先看到现场任务、点位状态和维护记录，不看全局财务。
- 财务/结算看退款、收入和导出，不操作设备与异常关闭。
- 数据查看员与审计员以只读为主，后续需要把只读权限和操作权限彻底拆开。
- 试运行操作员只能进入限定点位和试运行数据，真实上线时应和真实设备高风险动作、真实交易隔离。

## 4. 当前仍未完成

这些不是当前 MVP 阻塞项，但会影响真实上线：

- 当前登录态仍来自本地凭证适配器，但已具备会话有效期、过期重登和登录失败审计；后续需要接入真实认证、单点登录或企业账号体系。
- 邀请接受已具备前端链路、过期拦截和账号创建，但真实上线还需要邮件/短信投递、签名 token、密码策略、账号锁定和服务端 IAM 创建账号。
- 菜单权限、数据范围和动作权限仍在前端样例策略中执行，后续需要服务端返回权限矩阵并在 API 层二次校验。
- 目前已在角色页展示前端动作权限矩阵，并把接口同步/补偿处理接入独立策略；后续需要由服务端返回完整权限矩阵，并在 API 层二次校验。
- 用户基础账号范围仍主要以字符串表达；角色实例授权已先写入结构化范围对象，后续需要把账号基础范围、设备组和跨范围组合全部改成服务端 ID 关系。
- 工作台已按角色展示当前账号职责和优先队列；后续仍应把现场、客服、财务、审计等高频角色深化成更聚焦的首页视图。
- 权限生命周期已有前端复核审批、有效期和回收审批；仍缺服务端到期冻结、临时授权、委托审批和自动复核任务。
- 审计留痕仍是前端样例记录，真实系统必须记录操作者、来源设备、IP、前后值、审批意见和不可篡改日志。

## 5. 本轮前端实测

2026-07-06 已在 `http://127.0.0.1:5173/roles`、`/reports`、`/releases` 验证：

- 直接访问 `/roles` 会进入 `/login`，错误密码不能进入后台，正确登录后进入工作台。
- 控制台侧边栏提供退出登录，退出后回到 `/login`。
- 登录成功后侧边栏显示会话有效期；旧会话过期或缺少有效期时需要重新登录。
- `/` 工作台显示当前账号职责、工作重点、处理节奏、动作边界、权限包和角色相关优先队列，不再只是同一套经营总览。
- `/` 对没有报表或配置发布权限的账号隐藏交易额、退款售后和配置发布快照，改为显示当前范围内的交付完成、现场确认和设备状态。
- `/roles` 侧边栏底部只显示当前登录账号，不存在账号切换控件，也没有“演示账号”“演示操作员”“一键切换”等正式界面文案。
- `/roles` 使用“登录账号与职责”表达账号样例，不把账号样例做成后台内切换身份的操作。
- `/roles` 使用“当前账号动作权限”展示模块内动作边界，能看到某个菜单不代表能编辑、导出、审批或执行危险动作。
- `/roles` 角色实例支持配置、复核审批和回收审批；复核与回收必须填写依据，审批通过后才延长有效期或回收权限，并写入 L4 审计和同步请求记录。
- `/roles` 角色实例配置使用“范围层级 / 具体范围 / 写入范围”，不再要求管理员手填一段数据范围字符串。
- `/invitations/INV-001/accept` 在已登录状态下要求先退出当前账号；未登录时可设置密码接受邀请，接受后账号显示为“待授权用户”，登录后只看到授权等待页，随后可被租户管理员绑定到角色实例并提交审批。
- 角色实例审批通过后，侧边栏显示当前生效角色和生效范围；点位级授权只开放对应点位，不因范围文案中的城市字段扩大到同城其他点位。
- 业务负责人登录 `/roles` 后可见审批队列，但角色实例列表中的“配置 / 复核 / 回收”均不可操作，提示其只能查看权限、不能提交角色管理动作。
- 租户管理员登录 `/roles` 后可以邀请用户；对已回收的角色实例只能重新配置并进入启用审批，不能提交复核或回收。
- `/reports` 使用“系统同步状态”和“同步请求记录”，不再提供手工记录服务端成功/失败回调；同步失败后的高风险处理使用“补偿处理”口径。
- `/reports` 的提交同步和补偿处理按动作策略禁用；数据查看员、审计员等只读角色只能查看同步记录，不能提交同步或补偿。
- `/releases` 新建发布表单不再预填假案例；除发布对象外均为空值，依靠真实输入和占位提示完成提交。

## 6. 验收方式

下一轮验收时，不应只检查默认账号。建议在验收环境中用不同账号登录后逐项检查：

1. 平台支持、租户管理员、业务负责人：验证组织、权限、报表和审批边界。
2. 运营负责人、点位负责人：验证点位、请求、异常、任务闭环。
3. 客服/售后、退款审批人、财务/结算：验证退款发起、审批、复盘和导出边界。
4. 商品/配置管理员、场景模板管理员、配置发布人、配置审批人：验证配置编辑、发布和审批分离。
5. 机器人/设备运维、设备运维负责人、现场维护员：验证设备事件、命令、现场任务和数据范围。
6. 数据查看员、审计员、试运行操作员：验证只读、审计和试运行隔离。
