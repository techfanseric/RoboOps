# RoboOps 建设实施总计划与 Agent 分工

整理日期：2026-07-05
系统英文名：RoboOps
系统中文名：机器人商业运营平台

## 1. 建设原则

RoboOps 的建设不应从页面堆砌开始，而应按“产品定义、模型抽象、权限组织、工程骨架、场景样板、验证闭环”的顺序推进。

本期目标：

- 先做 MVP 框架，不做完整行业中台。
- 先跑通样板场景，不把样板写死为系统边界。
- 先用模拟数据证明业务闭环，再接真实 API。
- 先建立可配置模型，再扩展垂直行业深度。
- 先让客户能理解怎么运营，再让工程逐步自动化。

## 2. 标准建设步骤

### Step 0：统一口径

已完成。

产物：

- `00-项目索引.md`
- `99-文档一致性巡检记录.md`

验收标准：

- 所有文档都明确 RoboOps 是面向多场景的机器人商业运营平台。
- 所有文档都明确甲方缺少运营经验时，由 RoboOps 先给默认方案。
- MVP 范围、术语、后续编号不冲突。

### Step 1：产品需求冻结

目标：

- 把系统规划转成 MVP PRD。
- 明确用户、场景、模块、流程、边界、验收标准。

产物：

- `07-PRD-v0.1.md`

验收标准：

- 能作为产品、设计、前后端、测试共同参考的需求基线。
- 每个 MVP 模块都有目标、范围和不做事项。

### Step 2：信息架构与页面清单

目标：

- 把运营对象转成后台菜单、页面和操作。
- 明确每个页面服务什么角色、展示哪些字段、有哪些动作。

产物：

- `08-信息架构与页面清单.md`

验收标准：

- 能直接指导前端路由、页面组件和原型设计。
- 覆盖工作台、品牌或组织、场景模板、点位、设备、商品/服务、订单/请求、异常、任务、配置发布、报表、权限。

### Step 3：核心数据模型

目标：

- 建立可配置系统的底层数据结构。
- 明确租户、品牌、场景、点位、设备、商品/服务、订单/请求、异常、任务、角色权限之间的关系。

产物：

- `09-核心数据模型ERD.md`

验收标准：

- 能指导后端建表、API 设计和前端 mock 数据。
- 饮品字段不进入核心模型，只进入场景模板示例。

### Step 4：MVP 工程骨架

目标：

- 在仓库中创建可运行的前端应用骨架。
- 用模拟数据做出第一版可演示后台。

当前执行状态：

1. 静态 MVP 原型已完成：用于验证信息架构、样板数据、图标语义和真实运营闭环。
2. 正式 React/Vite 工程已完成首轮升级：当前以 `app/src/` 为唯一前端源码入口。

正式工程技术路线：

- 前端：Vite + React + TypeScript。
- 路由：React Router。
- 状态：本地 mock 数据 + React reducer，所有经营动作通过服务层更新共享状态。
- 样式：CSS 变量 + 模块化组件，不引入重型设计系统。
- 图标：Lucide React，按导航和动作语义选择。
- 后端：本期先不搭真实服务，后续根据 API 和数据模型再接入。

产物：

- Vite 入口：`app/index.html`、`app/vite.config.ts`。
- React 源码：`app/src/main.tsx`、`app/src/App.tsx`。
- 类型与数据：`app/src/types/`、`app/src/data/`。
- 业务服务层：`app/src/services/`。
- 页面与组件：`app/src/pages/`、`app/src/components/`。

验收标准：

- 本地可启动。
- 能看到完整后台框架。
- 至少能演示一个品牌、两个场景模板、多个点位、机器人/设备、商品/服务、订单/请求、异常、角色权限。
- `npm run check` 和 `npm run build` 必须通过。
- 浏览器必须能打开全部一级路由。
- 异常转任务、转退款、关闭、任务解决等动作必须能联动相关请求、任务、退款、日志和报表事实。

### Step 5：样板场景实现

目标：

- 跑通“饮品亭”样板。
- 跑通“通用机器人服务站”样板。
- 证明核心模型保持通用，饮品语义由场景模板承载。

产物：

- 样板品牌。
- 样板点位。
- 样板设备。
- 样板商品/服务。
- 正常订单和异常订单。
- 角色账号和权限示例。

验收标准：

- 同一套页面能切换查看不同场景。
- 饮品相关词只出现在饮品亭模板中。
- 异常能看到默认负责人、状态、SOP 和处理记录。

### Step 6：真实 API 接入准备

目标：

- 在不阻塞 MVP 原型的前提下，为真实 API 接入预留接口层。

产物：

- API 适配层目录。
- 本地样例服务与真实 service 的接口约定。
- API 字段映射清单。

验收标准：

- 后续拿到真实 API 后，不需要推翻前端页面和核心类型。

### Step 7：验证与迭代

目标：

- 用 Demo 和文档验证产品方向。
- 把客户/内部反馈转成配置项、MVP 修正或后续版本。

产物：

- 验收清单。
- 演示脚本。
- 问题记录。
- 下一版 backlog。

验收标准：

- 能向没有运营经验的甲方解释“这套业务怎么组织、怎么配置、怎么运营、怎么处理异常”。

## 3. Agent 分工

本轮采用一个主 agent + 三个文档子 agent 的方式并行推进。

### 主 agent

职责：

- 维护总计划。
- 搭建前端工程骨架。
- 实现 MVP 可演示页面。
- 集成子 agent 产物。
- 运行检查和最终交付。

当前写入范围：

- `docs/06-建设实施总计划与Agent分工.md`
- `docs/00-项目索引.md`
- `docs/99-文档一致性巡检记录.md`
- `app/`

### PRD Agent

职责：

- 输出 `07-PRD-v0.1.md`。
- 将现有规划转成可交付需求。

写入范围：

- `docs/07-PRD-v0.1.md`

### 信息架构 Agent

职责：

- 输出 `08-信息架构与页面清单.md`。
- 定义后台菜单、页面、字段、操作、跳转。

写入范围：

- `docs/08-信息架构与页面清单.md`

### 数据模型 Agent

职责：

- 输出 `09-核心数据模型ERD.md`。
- 定义核心实体、字段、关系、状态枚举和权限实体。

写入范围：

- `docs/09-核心数据模型ERD.md`

## 4. 首轮工程实现范围

首轮不做登录、不接真实 API、不做复杂持久化，先完成可演示 MVP 骨架。

页面范围：

- 工作台。
- 品牌或组织。
- 场景模板。
- 点位管理。
- 机器人/设备管理。
- 商品/服务目录。
- 订单/服务请求中心。
- 异常中心。
- 任务/工单。
- 配置发布。
- 报表。
- 用户、角色与权限。

交互范围：

- 左侧导航切换模块。
- 全局品牌/场景筛选。
- 样板数据展示。
- 异常状态推进。
- 订单/请求详情查看。
- 角色模板和权限包查看。
- 配置发布记录查看。

## 5. 本轮不做

- 真实登录认证。
- 真实多租户隔离。
- 真实支付、退款。
- 真实设备命令。
- 真实 OTA。
- 真实工作流引擎。
- 完整移动端。
- 完整后端服务。

这些能力进入后续版本。

## 6. 当前立即执行顺序

1. 文档子 agent 并行产出 `07/08/09`。
2. 主 agent 搭建 `app/` 前端工程。
3. 主 agent 实现模拟数据和页面骨架。
4. 子 agent 完成后，主 agent 更新索引和一致性记录。
5. 运行本地 dev server，做基础验证。
6. 输出本轮交付说明。
