# RoboOps PRD v0.1 - MVP 产品需求文档

整理日期：2026-07-05
系统英文名：RoboOps
系统中文名：机器人商业运营平台
文档状态：v0.1 可评审稿

## 1. 产品定义

RoboOps 是面向机器人、自动化设备与具身智能商业落地场景的可配置商业运营平台。它把租户/客户、品牌、场景模板、点位/场景单元、机器人/设备、商品/服务、订单/服务请求、履约状态、异常、任务、人员角色、权限和经营数据组织成一套可复制、可配置、可运营的标准系统。

饮品亭、咖啡亭、奶茶亭是第一批样板场景，用来验证机器人商业运营的完整闭环。系统底层以场景模板、商品/服务属性、履约显示名和样板数据承载“饮品、门店、配方、杯型、出杯”等语义，核心模型保持通用。

一句话目标：

> 帮机器人公司把“能做演示的机器人/设备”变成“能被团队持续经营的商业点位网络”。

## 2. 背景与核心判断

第一批 RoboOps 甲方大概率是机器人公司、具身智能公司、自动化设备公司或新成立的运营主体。他们懂机器人、硬件、AI、工程接口，但不一定有成熟的商业运营团队，也未必知道客服、点位运营、设备运维、现场维护、退款审批、异常分派、配置发布应该如何分工。

因此，本期产品应在 API 展示之上提供可执行的运营闭环，并主动提供默认运营模型：

- 默认经营模式：客户自营、平台代运营、联合运营、加盟/区域代理。
- 默认团队模板：最小运营团队、试点运营团队、城市复制团队、平台代运营团队。
- 默认角色模板：业务负责人、租户管理员、运营负责人、点位负责人、客服/售后、机器人/设备运维、现场维护员、商品/配置管理员、退款审批人、财务/结算、审计员、平台支持。
- 默认异常分派：支付、订单、机器人执行、设备离线、物料不足、顾客未取走、退款争议、配置错误等异常自动建议负责人和升级对象。
- 默认权限与风险控制：退款、停业、配置发布、设备高风险命令、数据导出必须有权限、审批或二次确认扩展位。

产品规划原则：

- 先给标准方案，再让客户基于实际人员、点位、设备和经营模式裁剪。
- 用配置承载客户差异，让不同客户的做法沉淀成可复用模板。
- MVP 先跑通可配置框架和一个样板业务闭环，不追求完整行业中台。
- 保留租户、品牌、场景模板和数据范围模型，界面上可先支持少量客户、少量品牌、少量模板。

## 3. MVP 目标

本期 MVP 的目标是交付一套可演示、可试点、可继续扩展的机器人商业运营后台骨架。

### 3.1 业务目标

- 让一个机器人商业样板场景能够被配置、上线、接单、执行、异常处理和复盘。
- 让没有成熟运营团队的甲方可以根据系统推荐搭建最小运营组织。
- 验证 RoboOps 的多场景可配置能力。
- 支撑从 1-3 个样板点扩展到 3-20 个试点点位的基础运营。

### 3.2 产品目标

- 不改代码即可创建品牌、点位、商品/服务、角色和基础场景配置。
- 至少内置两个场景模板：饮品亭、通用机器人服务站。
- 支持订单/服务请求从创建、支付、执行、交付到异常/退款的生命周期展示。
- 支持设备/机器人状态、事件日志与订单/异常联动。
- 支持异常生成、分派、处理、关闭和转任务/退款占位。
- 支持默认团队、角色权限、数据范围、异常责任人和基础审批策略。
- 提供工作台和基础报表，让运营人员每天知道哪里在营业、哪里异常、谁在处理。

### 3.3 验收目标

MVP 验收时，应能完成以下演示：

1. 创建一个租户/客户、一个品牌和一个组织/区域。
2. 选择“饮品亭”或“通用机器人服务站”场景模板，生成默认字段、状态显示名、异常字典和角色建议。
3. 创建点位，绑定机器人/设备，设置营业状态和负责人。
4. 配置商品/服务、SKU/规格/选项、适用点位和履约模板。
5. 创建或接入一笔订单/服务请求，查看完整生命周期和执行事件。
6. 从设备事件、订单超时或人工录入生成异常。
7. 系统按默认规则把异常分派给客服、运营、设备运维或现场维护角色。
8. 处理异常并记录过程，必要时转任务、转退款占位或关闭。
9. 查看工作台中的点位、设备、订单/请求、异常、任务和关键统计。
10. 证明饮品相关文案来自场景模板配置，核心模型仍使用商品/服务、点位/场景单元、订单/服务请求、异常/事件、任务/工单等通用术语。

## 4. 用户与使用场景

### 4.1 主要用户

| 用户 | 典型目标 | MVP 关注点 |
| --- | --- | --- |
| 业务负责人 | 判断试点是否能跑、是否值得扩点 | 看全局经营数据、审批关键动作、了解重大异常 |
| 租户管理员 | 初始化组织、人员、角色和数据范围 | 邀请用户、配置角色、分配数据范围 |
| 运营负责人 | 每天保证点位能营业、订单能闭环、异常有人处理 | 工作台、点位、订单、异常、任务、报表 |
| 点位负责人 | 管理单点位或少量点位日常状态 | 点位状态、订单、异常、现场任务 |
| 客服/售后 | 处理用户侧问题、未取货、退款沟通 | 订单详情、异常上下文、退款发起占位 |
| 机器人/设备运维 | 处理离线、故障、执行失败和日志排查 | 设备状态、事件日志、命令记录、异常处理 |
| 现场维护员 | 到现场补给、清洁、维修、确认问题 | 点位任务、处理记录、现场反馈 |
| 商品/配置管理员 | 维护商品/服务、规格、可售点位和模板配置 | 商品/服务目录、场景字段、配置发布 |
| 财务/结算 | 复核收入、退款和导出数据 | 交易统计、退款记录、导出权限 |
| 审计员 | 检查权限、高风险动作和操作留痕 | 操作日志、权限日志、高风险动作记录 |
| 平台支持 | 在客户缺团队时辅助交付和代运营 | 跨租户支持、初始化模板、排障记录 |

### 4.2 关键使用场景

- 新客户没有运营团队，系统通过团队搭建向导生成最小角色清单、权限模板和异常分派规则。
- 平台交付人员为客户创建品牌、点位、设备和样板商品/服务，快速搭建试点环境。
- 运营负责人每天进入工作台，查看待处理异常、离线设备、订单状态和现场任务。
- 顾客支付后订单没有成功下发到设备，系统生成异常并分派给运营调度和设备运维。
- 机器人执行失败，设备运维查看事件日志，客服同步看到订单上下文并决定是否发起退款。
- 顾客未取走商品或服务未确认，系统按超时规则生成异常，客服或现场人员确认后关闭或转售后。
- 商品/配置管理员修改商品可售范围，发布到指定点位，并留下配置发布记录。
- 业务负责人查看点位表现、异常排行和退款占位数据，决定是否扩点或调整运营模式。

## 5. MVP 范围

### 5.1 P0 必做范围

P0 是本期 MVP 必须交付并可演示的范围。

| 模块 | P0 能力 | 说明 |
| --- | --- | --- |
| 工作台 | 展示点位、设备、订单/请求、异常、任务关键数量和待处理事项 | 先做基础统计，不做高级 BI |
| 租户、品牌或组织 | 创建租户、品牌、组织/区域，维护基础档案和状态 | 多租户模型预留，界面可先支持少量客户 |
| 团队搭建向导 | 根据经营模式、点位规模、是否有客服/运维/现场团队生成推荐角色和责任分工 | 重点解决甲方没有运营团队的问题 |
| 用户与权限 | 用户管理、角色模板、角色实例、权限包、数据范围、用户多角色绑定 | 权限不只控制菜单，也用于异常分派和审批占位 |
| 场景模板 | 内置饮品亭、通用机器人服务站；支持字段、状态显示名、异常字典、推荐角色 | 验证场景语义配置化 |
| 点位管理 | 点位列表、详情、营业状态、负责人、绑定设备、适用商品/服务 | 使用“点位/场景单元”而非核心硬编码“门店” |
| 机器人/设备 | 设备台账、在线状态、运行状态、所属点位、能力标签、事件日志、命令记录 | 保留远程控制扩展位和命令审计 |
| 商品/服务目录 | 商品/服务类型、自定义属性、SKU/规格/选项、上下架、适用点位、绑定履约模板 | 饮品字段作为模板属性 |
| 订单/服务请求 | 列表、详情、支付状态、履约状态、执行事件、异常关联、退款/取消占位 | 先支持标准状态机和场景显示名 |
| 异常中心 | 异常列表、详情、等级、负责人、默认分派、处理记录、关闭、转任务/退款占位 | MVP 的核心差异化能力 |
| 任务/工单轻量版 | 从异常生成现场、客服、设备或人工确认任务；支持分派、处理、关闭 | 采用轻量任务闭环 |
| 配置发布记录 | 记录商品、点位、设备模板、场景模板发布人、时间、范围和版本 | 保留灰度发布扩展位 |
| 报表基础版 | 订单、点位、设备、异常、商品/服务基础统计和导出占位 | 导出受权限控制 |
| 操作日志 | 记录登录后关键业务操作、权限变更、高风险动作、配置发布 | 审计优先于自动化炫技 |

### 5.2 P1 可选增强

P1 可在 P0 稳定后进入，若两个月窗口期资源紧张可延后。

- 单级审批流：退款审批、配置发布审批、点位停业审批。
- 通知订阅：异常、设备离线、退款待审、配置发布结果通知。
- 异常 SLA：超时提醒、升级负责人、处理时长统计。
- 更多场景模板：无人零售站、机器人讲解站、机器人配送站。
- 演示数据管理：展会/Demo 点位、演示订单、演示异常一键重置。
- 移动端友好的现场任务页。

### 5.3 本期暂不做

- 完整消费者端小程序或 C 端 UI。
- 完整配方引擎和复杂制作步骤编排。
- 完整库存、仓储、采购、补货系统。
- 完整财务结算、分账、对账系统。
- 完整 OTA、远程调试、远程控制系统。
- 复杂 BPMN/Temporal 级流程引擎。
- 会员、优惠券、营销活动系统。
- 高级 BI、自定义报表设计器。
- 完整客服工单、排班、考勤、绩效系统。
- 多机器人空间调度、路径规划和交通编排。
- 外部 IAM/SSO 深度集成。

## 6. 核心业务流程

### 6.1 新客户初始化流程

1. 平台支持开通租户/客户；租户管理员在本租户内初始化组织、人员和数据范围。
2. 创建品牌，选择默认经营模式：客户自营、平台代运营、联合运营或加盟/区域代理。
3. 进入团队搭建向导，填写点位规模、是否自有客服、是否自有现场人员、设备运维归属、是否处理退款等信息。
4. 系统生成推荐组织结构、角色模板、默认权限包、异常分派规则、审批策略和上线检查清单。
5. 邀请用户并绑定角色实例；若客户没有对应人员，标记为平台代管或待补齐。
6. 创建组织/区域和点位，绑定负责人。

验收要求：

- 客户没有成熟运营团队时，系统必须能给出“谁负责什么”的默认方案。
- 每个点位至少有运营负责人、设备负责人、现场联系人。
- 每类 P0 异常至少有默认负责人和升级对象。

### 6.2 场景模板配置流程

1. 选择系统内置场景模板。
2. 查看模板包含的对象命名、字段、状态显示名、异常字典、推荐角色和报表指标。
3. 按品牌或点位进行轻量调整，例如商品/服务属性、状态显示文案、异常默认负责人。
4. 发布场景配置并生成配置发布记录。

P0 内置模板：

| 模板 | 目标 | 示例配置 |
| --- | --- | --- |
| 饮品亭 | 验证第一批咖啡/奶茶/制饮样板场景 | 杯型、温度、糖度、规格、待制作、制作中、待取杯、已取杯 |
| 通用机器人服务站 | 证明底层可支持非饮品场景 | 服务类型、服务时长、执行地点、预约时间、待派单、服务中、待确认 |

### 6.3 点位上线流程

1. 创建点位/场景单元，填写名称、编码、地址、组织/区域、营业时间和营业状态。
2. 选择场景模板和所属品牌。
3. 绑定机器人/设备，维护设备 SN、类型、型号、能力标签、在线状态。
4. 配置点位可售商品/服务范围。
5. 指定点位负责人、设备负责人、客服负责人、现场联系人。
6. 完成上线检查：设备在线、商品可售、负责人完整、异常规则有效、配置已发布。
7. 开启营业。

### 6.4 商品/服务配置流程

1. 选择商品/服务类型：饮品商品、实物商品、机器人服务、预约服务等。
2. 填写名称、编码、图片、状态、自定义属性。
3. 配置 SKU/规格/选项、价格占位、上下架状态。
4. 绑定履约模板和适用点位。
5. 发布配置到点位并记录版本。

P0 不要求复杂价格体系、优惠券、库存锁定和配方引擎，但必须保留字段扩展位。

### 6.5 订单/服务请求履约流程

标准底层状态如下，界面显示名由场景模板配置：

| 底层状态 | 默认中文 | 饮品亭显示示例 | 通用机器人服务站显示示例 |
| --- | --- | --- | --- |
| `created` | 已创建 | 已下单 | 已创建 |
| `pending_payment` | 待支付 | 待支付 | 待支付 |
| `paid` | 已支付 | 已支付 | 已支付 |
| `ready_to_execute` | 待执行 | 待制作 | 待派单 |
| `assigned` | 已分配 | 已下发设备 | 已派发机器人 |
| `executing` | 执行中 | 制作中 | 服务中 |
| `execution_completed` | 执行完成 | 出杯完成 | 服务完成 |
| `awaiting_delivery` | 待交付 | 待取杯 | 待确认 |
| `delivered` | 已交付 | 已取杯 | 已确认 |
| `not_delivered` | 未交付 | 未取杯 | 未确认 |
| `exception` | 异常 | 制作异常 | 服务异常 |
| `cancelled` | 已取消 | 已取消 | 已取消 |
| `refund_pending` | 退款处理中 | 退款处理中 | 退款处理中 |
| `refunded` | 已退款 | 已退款 | 已退款 |

P0 要求：

- 订单/服务请求详情页展示支付状态、履约状态、执行事件、关联设备、关联异常、处理记录。
- 状态变化必须留痕，记录来源系统、操作人、时间和备注。
- 支持由接口接入、模拟数据或后台创建样板订单。
- 支持超时规则生成异常，例如待执行超时、执行超时、待交付超时。

### 6.6 异常处理流程

1. 异常由订单事件、设备事件、超时规则或人工录入生成。
2. 系统根据异常类型、等级、来源、点位、场景模板匹配默认分派规则。
3. 异常进入异常中心，状态为新异常或已分派。
4. 负责人查看上下文：订单、点位、设备、事件日志、顾客影响、历史处理记录。
5. 负责人处理异常，可添加记录、改派、转现场任务、转退款占位、标记恢复或关闭。
6. 超时未处理时升级给上级角色。
7. 关闭异常时必须填写原因、处理动作和影响结论。

异常状态：

| 状态 | 含义 |
| --- | --- |
| `new` | 新异常，尚未分诊 |
| `triaged` | 已分诊，确认类型和等级 |
| `assigned` | 已分派负责人 |
| `processing` | 处理中 |
| `waiting_manual_confirm` | 等待人工确认 |
| `recovered` | 已恢复 |
| `closed` | 已关闭 |
| `converted_to_refund` | 已转退款 |
| `converted_to_field_service` | 已转现场处理 |

P0 异常类型与默认责任：

| 异常类型 | 默认负责人 | 升级对象 | P0 处理动作 |
| --- | --- | --- | --- |
| 支付失败 | 客服/售后 | 运营负责人 | 记录沟通、同步支付状态 |
| 已支付但未下发 | 运营调度/运营负责人 | 机器人/设备运维 | 重试占位、转设备排查 |
| 机器人接单失败 | 机器人/设备运维 | 运营负责人 | 查看设备状态和日志 |
| 执行超时 | 运营负责人 | 机器人/设备运维 | 等待、取消占位、转异常处理 |
| 制作/服务失败 | 机器人/设备运维 | 客服/售后 | 技术确认、客服跟进 |
| 顾客未取走 | 客服/售后 | 点位负责人 | 顾客沟通、现场确认 |
| 取货判断不确定 | 运营负责人 | 现场维护员 | 人工确认、关闭或转售后 |
| 物料/资源不足 | 现场维护员 | 运营负责人 | 转现场任务 |
| 设备离线 | 机器人/设备运维 | 现场维护员 | 远程排查占位、转现场 |
| 点位环境问题 | 点位负责人 | 运营负责人 | 停业占位、现场处理 |
| 退款争议 | 客服/售后 | 退款审批人 | 发起退款占位、留痕 |
| 配置错误 | 商品/配置管理员 | 配置审批人 | 修正配置、记录影响范围 |
| 安全风险 | 运营负责人 | 业务负责人 | 紧急停业占位、高优先级通知 |

## 7. 信息架构与页面需求

### 7.1 工作台

目标：让运营负责人和平台支持一眼看到当天是否能正常经营。

P0 内容：

- 今日订单/服务请求数量、异常数量、待处理任务数量。
- 运行中点位、暂停营业点位、异常点位。
- 在线设备、离线设备、异常设备。
- 待处理异常列表，按等级、超时、负责人排序。
- 最近配置发布记录。
- 快捷入口：新建点位、新建商品/服务、查看异常、查看设备。

### 7.2 租户、品牌或组织

P0 内容：

- 租户/客户列表与详情。
- 品牌列表与详情，包含名称、状态、默认场景、默认售后规则占位。
- 组织/区域列表，支持总部、城市、区域、点位组等层级。
- 品牌、组织、点位、人员之间的归属关系。

### 7.3 团队搭建向导

目标：客户缺少成熟运营团队时，系统主动给出组织建议。

P0 输入：

- 经营模式：客户自营、平台代运营、联合运营、加盟/区域代理。
- 点位规模：1-3、3-20、20-50、50+。
- 是否单品牌、是否跨城市。
- 是否有客服、现场维护、设备运维、财务复核人员。
- 是否需要处理退款。
- 是否有外部点位方或供应商登录。

P0 输出：

- 推荐组织结构。
- 推荐角色模板和待邀请账号清单。
- 默认权限包和数据范围建议。
- 默认异常分派规则。
- 默认审批策略。
- 上线前检查清单。

### 7.4 用户、角色与权限

P0 内容：

- 用户列表、邀请用户、启停用户。
- 角色模板库，包含最小运营团队、试点运营团队、平台代运营、联合运营、展会/Demo 模板。
- 角色实例详情：权限包、数据范围、审批能力、通知订阅、默认负责异常。
- 用户多角色绑定。
- 基础权限包：工作台查看、点位运营、商品服务管理、配置发布、订单处理、客服售后、退款审批、设备查看、设备运维、现场任务、报表查看、报表导出、资料查看、资料管理、用户权限管理、审计查看。
- 权限风险提示占位：退款发起和审批同人、外部供应商跨品牌权限、设备高危命令无二次确认等。

### 7.5 场景模板

P0 内容：

- 场景模板列表：饮品亭、通用机器人服务站。
- 模板详情：对象命名、启用模块、字段配置、状态显示名、异常字典、推荐角色、默认报表指标。
- 模板复制与启停。
- 模板发布记录。

### 7.6 点位管理

P0 内容：

- 点位列表，支持按品牌、区域、场景、营业状态、设备状态筛选。
- 点位详情：基础信息、营业状态、负责人、绑定设备、可售商品/服务、异常与任务。
- 点位启停状态记录。
- 点位上线检查清单。

### 7.7 机器人/设备管理

P0 内容：

- 设备列表，支持按点位、品牌、类型、在线状态、运行状态筛选。
- 设备详情：SN、类型、型号、能力标签、所属点位、在线状态、运行状态、最后心跳、版本信息。
- 设备事件日志。
- 命令记录：重启、暂停营业、恢复营业、同步配置等先作为记录和权限占位。
- 错误码到异常类型的映射占位。

### 7.8 商品/服务目录

P0 内容：

- 商品/服务类型管理。
- 商品/服务列表和详情。
- 自定义属性组。
- SKU/规格/选项。
- 上下架状态。
- 适用点位和场景模板。
- 绑定履约模板。
- 配置发布记录。

### 7.9 订单/服务请求中心

P0 内容：

- 订单/服务请求列表，支持按品牌、点位、状态、异常、时间筛选。
- 订单详情：基础信息、支付状态、履约状态、商品/服务、设备、执行事件、异常、任务、退款占位。
- 状态流转记录。
- 手动备注和人工确认。
- 创建样板订单或接入外部订单事件。

### 7.10 异常中心

P0 内容：

- 异常列表，支持按等级、类型、状态、负责人、点位、设备、超时筛选。
- 异常详情：异常信息、来源、关联订单/设备/点位、处理记录、SOP 文案、负责人、升级对象。
- 异常分派、改派、处理、关闭。
- 转现场任务、转客服处理、转退款占位。
- 手动创建异常。

### 7.11 任务/工单轻量版

P0 内容：

- 任务列表：现场任务、设备任务、客服任务、人工确认任务。
- 任务详情：来源异常、负责人、点位、处理要求、处理记录。
- 状态：已创建、已分派、处理中、等待外部条件、已解决、已关闭、已取消。

### 7.12 配置发布中心

P0 内容：

- 发布记录列表。
- 发布对象：商品/服务、点位配置、设备模板、场景模板。
- 发布范围：品牌、区域、点位、设备组。
- 发布状态、发布时间、发布人、版本号。
- 审批和回滚先做扩展位。

### 7.13 报表

P0 内容：

- 订单/服务请求统计：数量、状态分布、异常订单。
- 点位统计：营业点位、异常点位、订单量。
- 设备统计：在线率、离线次数、异常次数。
- 异常统计：类型排行、处理状态、负责人。
- 商品/服务统计：销量或请求量。
- 导出按钮可先做权限占位。

### 7.14 审计与日志

P0 内容：

- 操作日志：关键创建、编辑、发布、关闭、分派、审批占位动作。
- 权限日志：用户、角色、数据范围变更。
- 高风险动作记录：退款、停业、设备命令、配置发布、财务导出。
- 业务处理记录：异常、任务、售后沟通和设备处理过程必须留在对应业务对象下，不单独做“需求来源”或“资料归档”入口。

## 8. 权限与风险控制

### 8.1 动作风险等级

| 等级 | 类型 | 示例 |
| --- | --- | --- |
| L0 | 只读 | 查看列表、查看详情、看报表 |
| L1 | 普通编辑 | 编辑点位备注、维护联系人 |
| L2 | 业务影响 | 上下架、改价格占位、关闭异常、发起退款 |
| L3 | 高风险操作 | 重启设备、停业、恢复营业、发布配置 |
| L4 | 敏感管理 | 分配权限、导出财务、API 密钥、跨租户支持 |

### 8.2 MVP 默认权限原则

- 租户管理员负责用户、角色、组织和品牌基础配置，但不默认拥有退款审批和设备高危命令。
- 业务负责人拥有全局视图和关键审批能力，不负责日常设备操作。
- 运营负责人负责点位、订单、异常、任务闭环。
- 客服/售后可以发起退款或售后处理，但退款审批应由退款审批人、运营负责人或财务复核承担。
- 商品/配置管理员可以编辑商品/服务和模板，配置发布与审批建议分开。
- 设备运维可以查看日志和处理设备异常，高风险设备命令必须留痕和二次确认。
- 现场维护员只看自己的点位任务和基础状态，不看全局财务。
- 财务可看收入、退款和导出，不操作设备和异常关闭。
- 审计员只读，查看操作日志、权限日志和高风险动作记录。

## 11. 非功能需求

### 11.1 可配置性

- 核心模型使用通用术语，场景差异通过模板、字段、状态显示名和异常规则配置。
- 新品牌、新点位、新商品/服务、新角色应尽量不依赖代码发布。
- 饮品亭字段不能污染通用服务站字段。

### 11.2 可追溯性

- 状态变化、异常处理、配置发布、权限变更和高风险动作必须记录操作人、时间、来源、前后状态。
- 手动改状态、关闭异常、发起退款占位、设备命令记录必须留痕。

### 11.3 安全与隔离

- MVP 数据模型必须保留租户、品牌、组织/区域、点位数据范围。
- 跨租户平台支持行为必须记录。
- 导出、退款、设备高危命令、配置发布、权限分配属于敏感动作。

### 11.4 可运营性

- 工作台应优先展示“谁需要处理什么”，静态设备列表只是其中一类视图。
- 每个异常必须有状态、负责人、处理记录和关闭原因。
- 每个点位必须能看到负责人、设备、商品/服务、异常和任务。

## 12. 里程碑建议

### v0.1 产品骨架

目标：核心对象、页面框架和权限骨架可用。

- 工作台。
- 租户、品牌、组织。
- 用户、角色、权限包、数据范围。
- 场景模板。
- 点位、设备、商品/服务。
- 订单/服务请求。
- 异常中心。

### v0.2 配置模型跑通

目标：验证核心模型保持通用，饮品语义由模板承载。

- 饮品亭模板。
- 通用机器人服务站模板。
- 模板字段、状态显示名、异常字典。
- 配置发布记录。
- 样板数据。

### v0.3 样板场景试点

目标：用一个真实或半真实业务场景跑通闭环。

- 接入或模拟订单事件。
- 接入或模拟设备/机器人事件。
- 跑通订单生命周期。
- 跑通异常分派、处理、关闭。
- 跑通团队搭建向导和默认角色。

### v0.4 运营闭环增强

目标：支撑 3-20 个试点点位的日常运营。

- 异常 SLA 与升级。
- 任务/工单增强。
- 基础审批。
- 报表增强。
- 通知订阅。

## 13. 上线检查清单

每个试点上线前，系统应检查：

- 是否已创建租户、品牌、组织/区域。
- 是否已选择场景模板。
- 是否已创建点位并设置营业状态。
- 点位是否绑定至少一台机器人/设备。
- 设备是否有在线状态或模拟心跳。
- 点位是否配置可售商品/服务。
- 商品/服务是否绑定履约模板。
- 点位是否有运营负责人、设备负责人、现场联系人。
- P0 异常类型是否有默认负责人和升级对象。
- 客服/售后、设备运维、现场维护、退款审批等职责是否有人承担或标记平台代管。
- 高风险动作是否有权限和日志记录。
- 工作台是否能展示点位、设备、订单/请求、异常、任务数量。

## 14. 待确认事实资料

以下内容仍需从内部或甲方获取，但它们是事实输入，不是等待甲方从零定义产品。

- 当前 API 文档、订单状态字段、支付回调字段。
- 当前设备/机器人状态字段、错误码、事件日志格式。
- 小程序或外部订单系统是否已存在。
- 支付和退款主体、收款账户、退款接口归属。
- 第一批真实试点点位、设备组合、营业模式和订单量。
- 已发生过的 5-10 个真实异常案例。
- 第一版是平台代运营使用，还是直接给客户登录使用。
- 两个月窗口期的准确里程碑、试点客户、工程资源和验收场景。
- 是否需要展会/样板间 Demo 数据和演示账号。

## 15. 成功标准

MVP 成功意味着 RoboOps 具备机器人商业运营平台的骨架：

- 样板点位能完成配置、营业、接单、执行、异常处理和复盘。
- 客户没有成熟运营团队时，系统能给出默认组织、角色、权限和异常分派方案。
- 饮品亭和通用机器人服务站能共用同一套底层对象，只改变模板字段、显示名和规则。
- 异常中心能把工程事件转成运营人员可理解、可分派、可闭环的问题。
- 权限模型能支撑最小权限、数据范围、审批占位和操作审计。
- 后续扩展到更多品牌、点位、机器人/设备和场景时，不需要推翻核心模型。
