# RoboOps 当前实现与规划差异审查

整理日期：2026-07-05
审查对象：`/Users/ericyim/RoboOps/app`
对照范围：`docs/00` 至 `docs/15`

## 1. 总体判断

当前 React/Vite MVP 已经符合文档中的主方向：RoboOps 是机器人商业运营平台；本期目标是搭出可配置框架，并用样例数据跑通一条可运营闭环。

本轮审查前，主要差异不在页面数量，而在“真实后台感”：

- 权限、数据范围、审批、日志已经在文档中被定义为核心能力，但实现中仍有部分入口没有真正受控。
- 侧边栏数量、审批队列、操作日志等位置还残留静态演示口径。
- 配置化模型已经在文档和类型中出现，商品/服务目录、点位配置、场景模板、品牌、组织、设备配置、设备命令、用户邀请接受和角色实例已先接入发布/审批闭环；通用配置发布、对象级发布和角色实例授权已写入结构化范围；对象级配置发布已具备受控回退申请和反向应用；租户/客户开通、用户邀请、受邀账号创建和角色实例审批已具备前端业务闭环，但服务端 IAM、邮件/短信投递、服务端版本锁和服务端化仍未完成。

本轮已补强权限与数据范围的关键前端闭环；剩余差异主要进入真实 API、真实权限系统、配置编辑器和服务端审计阶段。

## 4. 当前仍有的主要差异

### 4.1 P0：真实试点前必须解决

1. 服务端认证和服务端权限未接入。
   当前工程已有登录页、账号密码校验、未登录路由守卫、退出登录、会话有效期、会话过期重登和登录失败审计；但认证仍是本地凭证适配器，菜单过滤、路由守卫、动作权限和数据范围仍在前端样例策略层执行。真实上线必须由企业账号、SSO 或服务端 IAM 返回用户、角色、权限包、菜单和数据范围，并在 API 层二次校验。

2. 新客户初始化和配置编辑器仍需服务端化。
   商品/服务目录、点位配置、场景模板、品牌、组织和设备已经先跑通配置发布闭环；通用配置发布和角色实例授权已改为结构化范围选择；对象级发布已支持受控回退；租户/客户开通已能创建初始租户、品牌、组织和管理员邀请，用户邀请、接受、账号创建和角色实例审批链路已跑通；但邮件/短信投递、结构化字段校验、服务端 IAM、服务端版本锁、冲突合并和服务端持久化仍缺。文档要求“这些都可以配置出来”，因此后续必须把当前对象级表单升级为正式配置编辑器和后端配置模型。

3. 团队搭建仍需服务端化。
   当前已经可以根据经营模式和规模生成角色实例，并绑定账号、数据范围和权限包；角色实例启用、复核和回收已进入前端审批流，审批通过后才会影响前端动作权限或权限生命周期，并已补有效期、回收审批、用户邀请接受链路和角色管理发起人限制。后续仍需补外部供应商身份、平台代管责任和服务端 IAM 执行。

4. 真实 API 网络层未接入。
   当前关键动作已经能生成服务端同步记录，包含方法、路径、风险、对象、业务状态、幂等键、同步状态、失败原因、服务端请求号、重试次数和补偿处理；报表页可提交同步、查看等待确认状态，并对高风险失败提交补偿处理。后续仍需接真实 HTTP client、对象级补偿执行、自动重试、服务端分页和真实数据同步。

5. 服务端审计不可篡改能力缺失。
   当前日志是前端样例记录，能表达产品语义，但不能满足真实追责。后续需要操作者 ID、IP/设备、前后值、审批意见、关联对象和不可篡改存储。

### 4.2 P1：影响试点质量

1. 配置范围仍需后端 ID 化。
   通用配置发布、商品/服务、点位、场景模板、品牌、组织、设备和角色实例授权已写入结构化 `scopeRef`，前端能展示范围层级、范围对象和写入范围。真实系统仍需把这些范围对象改成服务端 ID 关系，并补设备组、商品/服务集合、跨范围组合、范围冲突校验和 API 层二次授权。

2. 审批策略还不够完整。
   当前只有单级审批、自审拦截、角色和范围判断。文档中提到的金额阈值、影响范围阈值、超时升级、多级审批、委托审批还未实现。

3. 状态机和异常分派规则仍不够完整。
   场景模板已可变更业务对象、字段、履约状态、异常类型和责任角色；对象级配置已具备前端回退申请和反向应用；但异常分派规则、状态迁移约束、字段类型校验、服务端版本锁和冲突处理还未产品化。

4. 报表仍是基础派生指标。
   当前报表可从经营事实推导，但没有趋势、分组钻取、导出文件、对账口径和经营复盘视图。

5. 附件能力需绑定具体业务对象。
   当前已明确项目材料不产品化。若后续真实业务需要客服录音、现场照片或设备排障附件，应挂在订单、异常、任务或设备记录下，并由对应对象的权限和审计规则控制。

6. 设备命令仍缺真实执行通道。
   当前已具备命令申请、低风险直接执行、高风险审批、执行结果、设备事件、审计记录和接口请求同步记录；真实试点仍需接设备通道、执行回调、失败/超时处理和重试策略。

7. 页面内权限矩阵仍需服务端化。
   前端已新增“当前账号动作权限”，并把报表同步/补偿处理从“可查看报表”中拆出；异常、任务、配置发布、设备命令、审批、角色管理等也已有动作策略。但这些策略仍在前端样例层，后续需要由服务端权限矩阵统一驱动前端状态和后端校验。

8. 权限生命周期仍不完整。
   当前已经有角色实例审批生效、复核审批延长有效期、回收审批和管理动作发起人限制；提交复核/回收后不会提前改变权限。但还没有服务端到期自动冻结、临时授权、委托审批和定期复核任务。

9. 角色首页仍需继续深化。
   工作台已经增加“当前账号职责”，能按角色显示工作重点、处理节奏、动作边界和优先队列；但现场维护、客服售后、财务结算、审计复核等高频角色仍需要更贴近日常动作的专属首页组件。

### 4.3 P2：产品成熟度问题

1. 局部文案仍有少量工程阶段感。
   大部分生硬文案已修正；后续主要需要继续打磨空状态、失败状态和真实接入后的错误说明。

2. 空状态和异常状态需要更具体。
   现在能显示空表或无权限，但还缺少“为什么为空、下一步由谁处理”的运营引导。

3. 移动端只验证了无横向溢出。
   现场维护员大概率需要移动端任务页，当前响应式能看，但还不是专门为现场处理优化。

4. 部分关联对象仍使用字符串。
   例如商品适用点位、用户基础 `scope`、部分审计对象和展示字段仍是可读字符串。发布范围和角色实例授权已开始写入结构化对象，但后续仍应把所有范围关系改成 ID 关联和服务端授权。

## 7. 建议下一步

建议下一轮不要继续补更多静态页面，而是按下面顺序推进：

4. 做正式审计模型：高风险动作记录前后值、操作者、审批、来源和关联对象。
5. 做现场任务移动端优化：让现场维护员能在手机上处理、记录和完成任务。
